## 4. 行为验收基线（从前代 862 测试映射）

新引擎 Phase 5 验收 = 以下场景在新架构下全部可执行且行为等价
（测的是行为，不是代码）：

**生命周期**
- E2E 全回合：turn.start → 流式 → 定稿，ack 全程 consumed，一回合一卡
- 回合外 deliver：静态卡、不劫持活跃卡、cron 溯源页脚
- turn.abort / watchdog 封卡：卡收敛、后续帧 fallback
- 停机 seal_all：活跃卡全部先定稿再关闭

**竞态**
- 建卡窗口并发帧：恰一张卡（Q3 守卫回归）
- 跨 chat 并行互不干扰
- 同 chat 新 turn 打断旧 turn：旧卡 seal、新卡建立
- 长回合（模拟 >540s）：续期触发、无 200850 中断

**clarify**
- 边界窗口：finalize 后 1.2s 内 clarify.request → 同卡暂停续流
- 窗口超时：真落定
- 表单三态渲染（select / multi_select / input；answered / unauthorized）

**降级**
- 首次卡片失败 → 该帧 fallback + chat 降级
- 冷却后恢复探测成功 → 回 CHAT_OK
- 持续失败 → 每 帧 fallback（消息全走原生，零丢失）

**渲染**
- 懒面板：纯 answer 回合无空面板
- 面板分组：多轮思考分组标题、工具行合并 (×N)、耗时标签回填
- 字节预算裁剪顺序与不可裁剪项
- 页脚：全字段 / 缺字段 / 中止原因 / 重复定稿不重放
- Golden 快照全绿（03 §8）

**legacy 兼容**
- 文本转换器：前代文本编码 → 事件流的转换语义与前代分类器一致
  （工具行/思考/围栏/通知行/去重后缀）

## 6. 待实测补充项 → L3 真火实测冻结（2026-11-20，scripts/e2e_real.py）

以下数值前代代码未沉淀显式常量或依赖运行时环境，已于 2026-11-20 经
**L3 真飞书验收**（真实租户 cli_a951…，群聊 oc_bf248…，引擎+渲染+传输
全栈直驱）实测冻结：

- [x] **限频形态（429/99991400）**：三档探针（14 路并发 / 25 连发顺序高速
  ≈5.7 次/s / 原始 HTTP 面顺序爆发）均未触发 99991400 与 Retry-After 头
  （本次配额余裕，按事实记录）。**实测捕获卡级频控新码 200937**（"card
  updated too frequently"，同元素并发竞速下出现）——已入册 errors.py 并归
  瞬态重试族；与 99991400（平台 API 级）分道。
- [x] **300317 自愈间隔**：同号重放必拒（msg="sequence number compare
  failed"）；跳号允许（0→30001 直接接受，前向任意跳均接受）；close→reopen
  →stream 最小链 **0.20s** 可达；`--long` 真时序（session_renew_age=60s
  钳制下限，12s/帧 ×8 帧）主动续期触发、无 200850 中断。
- [x] **锚定差异**：伪锚点 reply → **99992354** 确定性失效（"not a valid
  open_message_id or not exists"）——Q10 降级直发通道真火回归通过；群聊
  reply 形态正常。私聊 P2P 双验证待提供 DM chat_id 后补测。
- [~] **clarify 回调授权失败码集**：澄清卡真实投递且真实可点（引擎 PAUSED
  / resume 链路真火通过）；回调码集依赖平台回调接线（hermes 网关回调面），
  标 **MANUAL** 留 Phase 6 双跑阶段实测。
- [x] **字节预算真实浮动（重大发现）**：官方文档 30KB 口径与 CardKit 实体卡
  实测**严重不符**——`cardkit_create` **100KB 接受**（99990B 实测通过）、
  `cardkit_stream_element` 内容 **100KB 接受**、`cardkit_update` **99KB
  接受**；stream 内容真实上限在 100~120KB 之间（120KB 起 HTTP 400 +
  **99992402** "field validation failed"，非 200860）；**200860 在全部
  测量路径未复现**。处置：27000 本地预算保持不变（前代生产实测安全值，
  保守裕度继续提供缓冲），知识如实冻结，Phase 6 双跑阶段再评估是否放宽。

## 7. Phase 6 双跑对照冻结（2026-11-20，scripts/dual_run.py + docs/dual-run-report.md）

同一段 hermes 出站流（12 场景语料）分别驱动前代终态（old-hermes-ref
@ c826ee8，FrameComposer + 真实 build_streaming_card_v2 + 录制客户端）
与本平台全栈（HermesAdapter → 引擎 → 渲染 → 传输 → MockFeishuREST），
逐场景对照卡片数 / 原生回退 / 终值保真 / API 计数：

- [x] **消息永不丢红线跨实现成立**：全部场景双侧零静默丢弃；降级注入
  （create 确定性拒收 200860）旧/新均 4 帧全原生履行。竞态注入
  （流式首帧 + 进度行同刻齐发，10-12 事故形态）双侧均恰建 1 卡
  （旧 per-chat 锁 / 新 per-chat 队列+注册表，结构性根治互证）。
- [x] **发现项 F1（澄清窗口可达性）**：边界 finalize 后适配器注册表已
  注销，hermes `send_clarify`（<200ms 跟随）触达不了引擎
  `clarify_window_hit`（L2 已证语义、适配器够不着——L1/L2 各自全绿但
  集成面断裂，双跑独有的发现形态）。修复：适配器宽限册（最近关闭
  回合 + 时间戳，窗口 = 引擎 `clarify_window_sec` 对齐 1.2s），窗口
  命中重开注册表（seq/thinking/Q9 状态全连续），过期 → 原生 ask。
- [x] **发现项 F2（无标记进度升格）**：edit-transport 工具气泡首发
  无标记，冻结契约「无标记 → deliver」会散卡刷屏；前代 v2.0.1 升格
  主链（v2.0.4/v2.0.8/v2.0.31 修订）移植为 `lt.upgrade_plain`，
  05-adapters §5.1 映射表同步修订。
- [x] **发现项 F3（cron 家族溯源）**：`job_id` 帧（官方调度标记）此前
  走微回合卡、包装头原文上卡、job_id 溯源丢失；`lt.parse_cron_delivery`
  移植 + `_deliver_cron` 路由（标题/正文剥离 + `footer.job_id`），
  前代 R1 规则对齐。
- [x] **同卡澄清续流 = 协议增强（非回归项）**：旧 edit-transport 定稿后
  结构性无法续写（FIX-3 迟到 edit 丢弃语义 + active_state 过滤 finalized），
  澄清续流=2 张回合卡；新架构宿主携 `turn_id` 即同卡续流

  发生（TrimReport 打点零触发）；Phase 5 真火结论维持——**27000 保持
